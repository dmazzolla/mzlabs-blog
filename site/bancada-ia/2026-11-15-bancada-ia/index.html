A AWS mostra como medir o custo por tarefa resolvida.

1/8

Preço por token não mostra quanto custa concluir uma tarefa. A AWS publicou um exemplo que estima o custo por tarefa que passa nos testes.

Destaque: NVIDIA NeMo Switchyard com LiteLLM no Amazon Bedrock. O Switchyard é uma biblioteca aberta que escolhe qual modelo atende cada pedido do agente. O post sobe o LiteLLM, gateway aberto, com o plugin Switchyard na sua conta AWS e estima o custo por tarefa que passa nos testes. Seu time paga agente de código e precisa justificar a conta? Comece por aqui. Os custos são estimativas do runner, não valores da fatura. Código de exemplo, fora de produção. O benchmark roda na sua máquina código Python escrito pelo modelo, sem isolamento: use um ambiente descartável. Fonte: blog de Machine Learning da AWS, 13/11.

Cliente Python do Kubernetes: engenheiros do Google Cloud e o SIG API Machinery estão modernizando o cliente oficial, baixado mais de 73 milhões de vezes por mês no PyPI. Fonte: Google Open Source Blog, 12/11.

XYBench: benchmark com 8.115 perguntas que testa se o assistente percebe uma premissa errada na pergunta. Segundo o estudo, os cinco modelos avaliados foram menos propensos que as respostas humanas de referência a desestimular a abordagem errada e orientar para o objetivo real. A avaliação usou uma resposta por pergunta, com o Sonnet 4.5 como juiz automatizado. Fonte: blog do Hugging Face, 13/11.

Linger: agente pessoal que, segundo o projeto, roda no próprio computador com modelos locais. O projeto se diz aberto, mas o GitHub não identifica a licença. Vai avaliar? Comece com dados fictícios e revise as permissões antes de conectar e-mail ou agenda de trabalho. Fonte: repositório simplexai-labs/linger no GitHub, criado em 10/11.

Destaque · 2 de 3 · como testar

Três passos para comparar na sua conta.

  • 1Conta AWS fora de produção, com acesso no Bedrock ao Claude Opus 5.5 e ao Nemotron 3 Super 120B. AWS CLI v2, região preparada para o CDK, Node 20+, Docker com BuildKit e Python 3.11+.
  • 2Clone o exemplo da aws-samples e siga os passos 3 e 4 do post: HTTPS, acesso só do seu IPv4, scripts/preflight.sh, cdk diff, cdk deploy e o teste do gateway.
  • 3Rode bench/run.py com --model switchyard e com cada grupo de modelo único. Compare SOLVED e depois COST/SOLVED. O custo é estimado pelo runner, não é a fatura.
Destaque · 3 de 3 · cuidados

Olhe primeiro quantas tarefas foram resolvidas.

Segundo o post, um grupo que resolve menos pode parecer mais barato por tarefa e custar mais por tarefa resolvida. Poucas execuções não bastam para concluir nada sobre custo ou qualidade.

O benchmark roda na sua máquina o Python escrito pelo modelo, sem isolamento do sistema: o código pode ler seus arquivos e acessar a rede. Use um ambiente descartável, sem credenciais AWS duradouras no disco. Código de exemplo e integração experimental, fora de produção. Chamadas ao Bedrock são cobradas. Apague a pilha no fim.
